ABSTRACT & EXECUTIVE SUMMARY

Modern computerized assessment and educational resource distribution portals are severely impeded by three foundational engineering limitations:

  1. Unstable External Repository Dependencies: Many educational platforms merely hyper-link to external government or third-party servers (such as the Maharashtra State Board cart.ebalbharati.in server). During critical examination and study cycles, these remote endpoints frequently experience network timeouts, SSL certificate handshake failures, or server crashes.
  2. Connectivity Fragility in Remote & Semi-Urban Classrooms: In regions with intermittent broadband or fluctuating 4G networks, momentary packet drops during live computer-based tests sever candidate sessions, causing data loss, exam anxiety, and distorted grading.
  3. Superficial Evaluative Depth: Traditional quiz engines calculate aggregate percentage scores without diagnosing cognitive depth (Bloom's Taxonomy) and fail to provide students with authentic subjective past board examination papers.

To overcome these structural limitations, QuizNova-AI was conceptualized and developed. It is a full-stack, enterprise-grade, offline-resilient assessment and curriculum delivery ecosystem engineered using Next.js 14 App Router, React 18, Node.js, Express.js, TypeScript, and Prisma ORM with a Single Unified SQLite Database.

Key Architectural Pillars:

  • 1-Click Google Authentication & Direct Academic Registration: Eliminates external OTP SMS/email gateway failures by providing instantaneous, friction-free Google OAuth sign-in alongside direct academic credential registration.
  • 100% In-App Balbharati Digital Textbook Reader: Eliminates external server dependency by embedding 41 full-length digital textbooks for Classes 9, 10, 11, and 12 across Science, Commerce, and Arts streams with instant chapter navigation, theory reviews, and textbook exercise questions.
  • 36-Year Subjective Board PYQs Archive (1990 — 2026): A dedicated, distraction-free repository of authentic Maharashtra SSC and HSC question papers structured strictly by official Board blueprints with zero automated MCQs and zero answer spoilers.
  • Offline-First Secure Synchronization Engine: Allows candidates to download encrypted examination packages into client-side IndexedDB storage, complete examinations without active WiFi/cellular data, and automatically synchronize telemetry upon reconnection.
  • Cognitive Diagnostic Assessment: Maps question performance dynamically across all six cognitive tiers of Bloom's Taxonomy (Remembering, Understanding, Applying, Analyzing, Evaluating, Creating).
  • Anti-Cheating Web Proctoring Subsystem: Enforces full-screen compliance, monitors browser tab visibility, logs violation metrics, and prevents unauthorized examination navigation.

CHAPTER 1: INTRODUCTION

1.1 Project Overview & Background

In the contemporary era of academic transformation (Education 4.0), computer-based assessment and learning management systems have become essential to pedagogical infrastructure. However, despite rapid technological strides, educational institutions in India—particularly those affiliated with state boards such as the Maharashtra State Board of Secondary and Higher Secondary Education (MSBSHSE)—face substantial hurdles in delivering reliable digital examinations.

Digital learning portals currently deployed across colleges and coaching institutes suffer from severe operational limitations. When examinations are conducted online, institutions frequently experience high network contention, bandwidth saturation, or server crashes. Furthermore, when students seek authentic curriculum resources, they are routinely redirected to external government repositories (such as the Maharashtra State Board's cart.ebalbharati.in server). During peak examination seasons, these external servers frequently suffer from HTTP timeouts, SSL handshake failures, or slow response times, leaving students stranded without textbook access.

To address this challenge comprehensively, QuizNova-AI was developed. QuizNova-AI is an integrated, full-stack, AI-enabled, and offline-first assessment ecosystem. It consolidates computer-based examination authoring, automated cognitive diagnostics (Bloom's Taxonomy), ethical web proctoring, an internal 100% In-App Balbharati digital textbook reader for Classes 9 through 12, and a 36-year archive of authentic subjective past board examination papers into a unified, high-performance architecture.

1.2 Objectives

The central mission of QuizNova-AI is to provide an uninterrupted, high-integrity educational environment. The project pursues the following primary objectives:

  1. Provide Fault-Tolerant Offline Examination Execution: To architect an offline-first execution engine allowing candidates in low-bandwidth or zero-connectivity environments to download encrypted exam packs, complete time-bound assessments without active internet access, and synchronize results automatically when connectivity resumes.
  2. Eliminate Third-Party Server Dependencies via In-App Balbharati Reader: To internalize curriculum delivery by embedding 41 full-length, structured digital textbooks for Classes 9, 10, 11, and 12 across Science, Commerce, and Arts streams directly within the application, ensuring zero dependence on fragile external portals.
  3. Archive 36 Years of Authentic Maharashtra Board Subjective PYQs (1990 — 2026): To construct a distraction-free repository of authentic Maharashtra SSC and HSC question papers adhering strictly to official board blueprints with zero automated MCQs and zero answer spoilers, catering directly to subjective examination preparation.
  4. Implement Cognitive Depth Evaluation via Bloom's Taxonomy: To automatically categorize question performance across the six cognitive levels of Bloom's Taxonomy (Remembering, Understanding, Applying, Analyzing, Evaluating, Creating), providing actionable diagnostic insights rather than raw percentage scores.
  5. Enforce Browser-Based Anti-Cheating Proctoring: To integrate automated client-side proctoring that tracks window blur events, monitors document visibility changes, logs fullscreen exits, and automatically locks or submits examinations upon repeated infractions.
  6. Provide 1-Click Google Authentication & Instant Registration: To incorporate seamless Google OAuth sign-in alongside direct academic registration, completely bypassing unstable third-party SMS/email OTP gateways and ensuring candidates enter their examination dashboard in a single second.

CHAPTER 2: SYSTEM ANALYSIS

2.1 Problem Definition

The transition from paper-based examinations to online learning platforms has introduced major operational bottlenecks that hinder academic productivity:

  1. Unreliable External Textbook Repositories: A vast majority of state-board educational applications do not host syllabus materials locally. Instead, they embed hyperlinks directing students to the state repository (cart.ebalbharati.in). In real-world academic settings, this external server frequently experiences unexpected downtime, slow download speeds, or DNS resolution failures. Students studying for exams are left stranded without access to their curriculum.
  2. Session Termination from Transient Packet Loss: Standard web applications rely on a persistent client-server WebSocket or HTTP connection. When a student in a rural or semi-urban area experiences momentary network degradation, the assessment engine fails to record ongoing inputs, crashes the test state, or submits an incomplete attempt. This creates anxiety, disputes over grades, and unfair evaluations.
  3. Absence of Cognitive Depth in Evaluative Feedback: Typical computerized assessment portals generate simplistic score summaries (e.g., "75% - Pass"). Such metrics fail to provide diagnostic clarity. They cannot indicate whether a student has mastered basic memory recall (Remembering) but struggles with analytical problem solving (Analyzing or Applying). Without cognitive taxonomy mapping, instructors cannot design targeted interventions.
  4. Saturation of Generic MCQs vs Authentic Subjective Board Papers: Commercial test prep portals saturate their question banks with generic, uncurated multiple-choice questions. For students preparing for Class 10 and Class 12 board exams, subjective paragraph and analytical questions are paramount. Students have lacked an authentic, verified repository of Maharashtra Board past papers organized by year and syllabus stream that respects official blueprints without confusing AI-generated answer spoilers.

2.2 Requirement Analysis

2.2.1 Functional Requirements

  • FR-01: 1-Click Google Authentication & Direct Registration: The system must provide candidate authentication supporting 1-click Google OAuth sign-in alongside direct academic credential registration without requiring external OTP SMS/email steps.
  • FR-02: Role-Based Access Control (RBAC): The platform must distinguish between 'Student' and 'Educator' accounts, restricting exam authoring tools strictly to verified educators.
  • FR-03: Assessment Creation & Question Authoring: Educators must be able to create examinations with custom time limits, descriptions, point values, and question tagging based on the six levels of Bloom's Taxonomy.
  • FR-04: Secure Exam Player with Countdown Timer: The assessment interface must deliver a focused test-taking environment featuring an active timer, question navigation pagination, and automatic submission upon timer expiration.
  • FR-05: Real-Time Web Proctoring: The system must detect when an examinee shifts browser tabs or exits full-screen mode, issuing onscreen warnings and logging violations to the student's attempt record.
  • FR-06: In-App Balbharati Digital Textbook Reader: The application must embed 41 full-text digital textbooks for Classes 9, 10, 11, and 12 across Science, Commerce, and Arts with instant chapter navigation, theory reading, and exercise reviews without external redirection.
  • FR-07: 36-Year Subjective Board PYQs Archive: The portal must deliver authentic Maharashtra SSC and HSC question papers spanning from 1990 to 2026, filterable by Year, Standard, and Subject, strictly without MCQs or automated answers.
  • FR-08: Cognitive Diagnostic Reporting: Post-examination results must visualize percentage proficiencies across all six tiers of Bloom's Taxonomy to guide learner remediation.

2.2.2 Non-Functional Requirements

  • NFR-01: Performance & Response Time: Client-side route navigation must occur in under 500ms. Server API endpoints must respond within 200ms under standard institutional loads.
  • NFR-02: Reliability & Fault Tolerance: The frontend must handle API server disconnections gracefully using cached local sessions and local storage fallbacks, ensuring zero loss of in-progress test data.
  • NFR-03: Security & Cryptographic Protection: All user passwords must be hashed using bcrypt with a salt factor of 12. Authentication cookies must enforce HttpOnly, Secure, and SameSite policies.
  • NFR-04: Usability & Ergonomics: The user interface must comply with WCAG 2.1 AA accessibility standards, featuring high-contrast academic color themes, legible typography, and intuitive touch targets.
  • NFR-05: Portability & Cross-Platform Responsiveness: The system must render seamlessly across viewport widths from 360px (mobile smartphones) to 2560px (ultra-wide desktop monitors).

3.3 Use Case Diagram & Actor Descriptions

  • Primary Actors:
    • Student: Signs in via Google or direct account, attempts assessments, views real-time timers, receives proctor violation alerts, browses in-app Balbharati textbooks, reviews 1990-2026 subjective board question papers, and inspects cognitive performance scorecards.
    • Educator: Authenticates to educator portal, authors assessments, tags questions with Bloom's taxonomy categories, reviews cohort score analytics, and inspects student proctor violation audit logs.
    • System Scheduler: Auto-submits timed-out examinations and recalculates cohort averages.

3.4 Sequence Diagrams (5 Core Workflows)

  1. 1-Click Google OAuth & Direct Authentication: Client submits Google Token / Direct Credentials -> Server verifies integrity -> Queries or registers User -> Establishes authenticated session token -> Candidate navigates to dashboard.
  2. Educator Quiz Creation: Educator fills quiz metadata -> Adds questions with Bloom tags -> Submits payload -> Server validates schema via Zod -> Prisma persists Quiz and Questions transactionally -> Returns confirmation.
  3. Proctored Examination Attempt: Student launches quiz -> Full-screen mode engaged -> Timer starts -> Student switches tab -> Page Visibility listener fires -> Anomaly logged -> Exam submitted -> Bloom score computed.
  4. In-App Balbharati Textbook Streaming: Student selects standard (Classes 9-12) & subject -> Client requests embedded curriculum bundle -> Server serves verified digital textbook internally -> Content rendered in distraction-free reader.
  5. Subjective PYQ Filtering: Student filters by year (1990-2026) & stream -> Query executes -> Returns authentic Maharashtra Board question paper formatted strictly according to official board blueprints without answer spoilers.

3.6 Database Design & Data Dictionary

3.6.1 Data Model Overview & Normalization

The database is designed according to Third Normal Form (3NF) standards:

  • 1NF: Every table column stores atomic values; repeating groups are eliminated.
  • 2NF: All non-key attributes are fully functionally dependent on primary keys.
  • 3NF: Transitive dependencies are removed; foreign keys reference parent tables directly.

3.6.2 Purpose of Data Model

The schema guarantees zero data redundancy, enforces referential integrity through foreign key cascades, and accelerates high-concurrency exam submissions through indexed lookups.

6.5 Assessment Submission & Scoring Calculation Engine

// backend/src/controllers/quizController.ts
export const submitQuizAttempt = async (req: Request, res: Response) => {
  try {
    const { quizId, answers, cheatingFlags } = req.body;
    const studentId = (req as any).user.id;

    const quiz = await prisma.quiz.findUnique({
      where: { id: quizId },
      include: { questions: true },
    });

    if (!quiz) return res.status(404).json({ success: false, message: 'Quiz not found.' });

    let score = 0;
    const bloomMap: Record<string, { total: number; correct: number }> = {
      Remembering: { total: 0, correct: 0 },
      Understanding: { total: 0, correct: 0 },
      Applying: { total: 0, correct: 0 },
      Analyzing: { total: 0, correct: 0 },
      Evaluating: { total: 0, correct: 0 },
      Creating: { total: 0, correct: 0 },
    };

    quiz.questions.forEach((q) => {
      const level = q.bloomLevel || 'Understanding';
      if (!bloomMap[level]) bloomMap[level] = { total: 0, correct: 0 };
      bloomMap[level].total += 1;

      if (answers[q.id] && answers[q.id].trim().toLowerCase() === q.correctAnswer.trim().toLowerCase()) {
        score += q.points;
        bloomMap[level].correct += 1;
      }
    });

    const attempt = await prisma.quizAttempt.create({
      data: {
        quizId,
        studentId,
        score,
        totalQuestions: quiz.questions.length,
        bloomBreakdown: JSON.stringify(bloomMap),
        cheatingFlags: Number(cheatingFlags || 0),
      },
    });

    res.status(200).json({ success: true, message: 'Attempt recorded.', attempt });
  } catch (error) {
    res.status(500).json({ success: false, message: 'Failed to evaluate attempt.' });
  }
};

6.6 Anti-Cheating & Web Proctoring Telemetry

// frontend/src/hooks/useWebProctor.ts
import { useEffect, useState } from 'react';

export const useWebProctor = (onViolation: (count: number) => void) => {
  const [violations, setViolations] = useState(0);

  useEffect(() => {
    const handleVisibilityChange = () => {
      if (document.hidden) {
        setViolations((prev) => {
          const next = prev + 1;
          onViolation(next);
          return next;
        });
      }
    };

    const handleWindowBlur = () => {
      setViolations((prev) => {
        const next = prev + 1;
        onViolation(next);
        return next;
      });
    };

    document.addEventListener('visibilitychange', handleVisibilityChange);
    window.addEventListener('blur', handleWindowBlur);

    return () => {
      document.removeEventListener('visibilitychange', handleVisibilityChange);
      window.removeEventListener('blur', handleWindowBlur);
    };
  }, [onViolation]);

  return { violations };
};

export const calculateBloomPercentages = (breakdownJson: string) => {
  try {
    const data = JSON.parse(breakdownJson);
